\section{Dataset Taxonomy and Benchmark Scope}

The thesis relies on SpikeForest \parencite{Magland2020} as its source of information. SpikeForest is a benchmarking framework that assesses multiple spike sorters using ground-truth datasets. It is the largest source of combined ground-truth data publicly available, offering a collection of recordings from various laboratories, probes, and dataset types, including paired ground-truth recordings, simulations, and hybrid simulations. Using the hybrid simulation recordings and paired ground-truth recordings provided through that framework, we constructed a dataset where each data point represents a unit (a putative neuron) together with its features. As targets, we use the false negative rate \fmiss{} and the false positive rate \fpos{}.

\subsection{Paired Ground-Truth Recordings}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.82\textwidth]{paired_juxtacellular_setup.png}
    \caption{Paired ground-truth and extracellular recording setup. A ground-truth electrode records spikes from a single neuron, while a high-density probe simultaneously captures extracellular activity from surrounding neurons across multiple channels, enabling evaluation of spike-sorting accuracy.}
    \label{fig:paired-setup}
\end{figure}

Paired ground-truth recordings are comprised of two sensors, as shown in \cref{fig:paired-setup}. First, a probe with multiple channels is used to record the activity potential of nearby neurons. Channels are close to each other, and the activity of a single neuron often overlaps across multiple channels. The recording dataset is therefore a multivariate time series representing the recorded voltage over time for multiple channels.

The ground-truth electrode, on the other hand, is a glass micropipette recording from a single neuron. Its recording dataset is represented as a two-column matrix, with the first column indexing rows by timestamps and the second column recording high-amplitude voltage traces. Its proximity to the cell membrane allows it to capture almost every action potential in the 1--10 mV range, while multi-channel probes might detect them in the 100--500 \si{\micro\volt} range. This capacity to capture every signal from a single target neuron is what makes it a legitimate ground truth.

\subsection{Hybrid Simulations}

As mentioned in \cref{sec:background}, one of the main challenges of the field is obtaining realistic ground-truth data. Fully simulated datasets became very popular for benchmarking sorters, but they can only be so close to reality. To palliate this, hybrid simulation datasets emerged. Hybrid datasets are constructed by combining a real extracellular recording with artificially reinserted real neuronal spike waveforms whose spike times and identities are known exactly.

This approach offers two main advantages. First, it preserves the multi-channel noise structure and waveform variability. Second, it provides exact spike-time ground truth, enabling rigorous evaluation of the developed quality metrics. In contrast to synthetic simulations, hybrid simulations employ a realistic noise model and, unlike purely in vivo recordings, allow performance measurement with exact labels.

The primary assumption underlying hybrid simulations is that the reinserted templates accurately represent neuronal extracellular signatures under stationary recording conditions. The limitations of hybrid simulations include a potential underrepresentation of extreme waveforms and the fact that most neurons selected have a high signal-to-noise ratio.

\subsection{What Kind of Dataset Each Split Component Is}

\begin{itemize}
    \item \textbf{Hybrid labelled simulation data.} These units are the main supervision reservoir used in the transfer-learning process. They teach the model the task at scale.
    \item \textbf{Paired labelled ground-truth data.} These units are scarce but scientifically the most significant. They are used both to adapt the model to paired juxtacellular and intracellular ground-truth data and to evaluate final performance.
    \item \textbf{Paired unlabeled recording data.} These units cannot be used for supervised learning, but they preserve the structure of paired ground-truth recordings. They are useful for support estimation, pseudo-label selection, and representation learning. Units coming from held-out recordings remain excluded from any such use.
    \item \textbf{Leave-one-family-out partitions.} These are stricter evaluation views of the same paired ground-truth data in which one study family is removed from training and evaluated entirely at test time.
\end{itemize}

The final packaged dataset contains 33,206 rows from 61 recordings and 9 spike sorters, as summarised in \cref{tab:dataset-summary}. Of these rows, 24,224 come from hybrid simulations and 8,982 come from paired ground-truth recordings. However, out of the 8,982 paired rows, only 207 have the matched labels required for the supervised target benchmark. In paired ground-truth settings, only one neuron can be monitored per recording. The remaining 8,775 rows are putative units detected by the sorters that help us understand the recording context as well as the underlying structure of paired-recording data.

\subsection{Dataset Origins}

The paired portion of the benchmark spans five SpikeForest study families. Their coverage is summarised in \cref{tab:family-coverage}. All five were accessed through the SpikeForest framework \parencite{Magland2020}, which standardises probe geometry and already provides multiple spike-sorting outputs with accessible results.

\study{PAIRED\_BOYDEN} \parencite{doi:10.1152/jn.00650.2017} is a cortical paired dataset from mouse recordings and is particularly informative for bursting behaviour. \study{PAIRED\_CRCNS\_HC1} is a hippocampal dataset from anaesthetised rats, recorded with tetrodes and short silicon probes \parencite{doi:10.1152/jn.2000.84.1.401,Harris2001}. \study{PAIRED\_ENGLISH} \parencite{Magland2020} is the broadest study set in the package, spanning hippocampus, neocortex, and thalamus. \study{PAIRED\_KAMPFF} provides dense cortical polytrode recordings with paired juxtacellular micro-pipettes \parencite{Neto2016Paired}. \study{PAIRED\_MEA64C\_YGER} is the only ex vivo dataset in the package and targets retinal ganglion cells on a dense multielectrode array \parencite{10.7554/eLife.34518}.

\subsection{Dataset Audit}

Not all labelled paired rows have an \fmiss{} label because \fmiss{} is only defined for units with an explicit ground-truth match. We consider a neuron to be "matched" only when one of the neurons detected by the spike sorter has an accuracy score of at least 0.5 with the ground-truth neuron.

We require a valid match for \fmiss{} because missed spikes can only be counted relative to a specific ground-truth neuron. For an unmatched sorted unit, \fpos{} is more limited: we can only quantify the share of its assigned spikes that are inconsistent with the available matched ground-truth sources, so the resulting value should be read as a benchmark-side estimate rather than as a fully observed unit identity decomposition.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.9\textwidth]{{dataset_composition_audit copy}.png}
    \caption{Dataset composition audit. The benchmark combines a large labelled hybrid simulation dataset, a smaller unlabeled paired-recording dataset, and a paired labelled ground-truth dataset of only 207 rows.}
    \label{fig:dataset-composition}
\end{figure}

Our target \fpos{} is available for each row. However, not every row has \fmiss{} available. Therefore, we only train and test \fmiss{} models on rows with valid \fmiss{} labels, while we still include rows with missing \fmiss{} in the broader hybrid source package used during transfer learning where relevant, as illustrated in \cref{fig:dataset-composition}.

Additionally, the difference between hybrid simulation and paired data is not only in the number of rows. Hybrid rows are more uniform and easier to handle, while paired rows are more realistic and are split internally into different families with varying recording methods and biological settings. These differences shape which model might be more suited to certain family types and explain why the final story cannot be reduced to a single model configuration. This is also why it is important to distinguish between generalising across recordings of a family already present in training and generalising to entirely unseen family recordings.

\subsection{Domain-Shift Quantification}

In order to quantify the domain shift between hybrid simulation data and paired juxtacellular and intracellular ground-truth data, we train a simple logistic regression model \parencite{10.1111/j.2517-6161.1958.tb00292.x} from scikit-learn to classify units as paired or hybrid.

After that, we judge the separability of the two domains based on the model's Area Under the Curve (AUC). AUC is the preferred metric for quantifying domain shift because it measures how well the model separates the two classes across all thresholds, instead of judging it at only one cutoff.

Additionally, we build and evaluate a model trained on both the original feature dataset and the dataset augmented with context features. This tells us whether adding recording-level information on top of unit-level information increases the separability of the two domains.

\section{Feature Construction}

We built the dataset on derived features rather than raw voltage traces. Features were extracted directly from SpikeForest recordings and sorting outputs. The feature package is composed of waveform bins, autocorrelogram bins, amplitude statistics, SpikeInterface quality-control metrics, cosine-similarity features comparing units to neighbouring units, and recording-context features. We define each of these in detail below.

\subsection{Waveform and Autocorrelogram Features}

The waveform of a neuron is the shape taken by the signal when it fires, as illustrated in \cref{fig:waveform-template}. This waveform might vary in amplitude from spike to spike, but it is a direct product of the neuron’s physiology and its position relative to the probe. The shape of the mean waveform is commonly called a ‘template’. This template provides important information about whether a specific spike might belong to a certain neuron.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.94\textwidth]{waveform.png}
    \caption{Two spike waveforms going through similar phases but with different templates. The right waveform shows slower kinetics, suggesting a different neuron type.}
    \label{fig:waveform-template}
\end{figure}

An autocorrelogram allows us to analyse the temporal firing structure of a neuron by studying the distribution of spike occurrences across time lags relative to each other, as in \cref{fig:acg-quality}. It enables us to verify that putative units do not break the biological refractory period. The refractory period is the interval following a spike in which a neuron is physiologically unable to fire again. A putative unit breaking it indicates that it likely contains overlapping signals from different neurons.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.96\textwidth]{ACG.png}
    \caption{Schematic autocorrelogram comparison for spike-sorting quality assessment. The left panel shows a well-isolated unit with a pronounced refractory trough, whereas the right panel shows refractory-period violations consistent with contamination or multi-unit activity.}
    \label{fig:acg-quality}
\end{figure}

To give the model access to waveform- and autocorrelogram-rich information, we discretised the signal into fixed bins. The waveform is divided into 30 bins, while the autocorrelogram is discretised into 40 bins, with the refractory period centred around the 20th bin.

\subsection{Amplitude, Spike-Timing, and Quality-Control Features}

Amplitude features describe how large the spikes are, and amplitude-stability features describe how stable that size remains over time. These features are specific to each putative unit: the mean, spread, quantiles, variability, and drift-related changes of amplitude in the recording. They give the model clues about potential drift, poor isolation, or changing detectability, all of which are relevant for predicting false positives and missed spikes.

In addition to the autocorrelogram, we implemented multiple features to help the model understand the spike-timing tendencies of putative units. Examples include firing rate, spike count, burst tendency, and refractory-period violation rate. These features capture how often a unit fires, how regular it is, and whether it stays consistent over the recording.

SpikeInterface \parencite{Buccino2020SpikeInterface} is a standardised library for performing spike sorting end to end. We used it to compute its "quality-control package" over each putative unit, which includes signal-to-noise ratio, drift summaries, and amplitude cutoff. These features give the model direct access to the type of post-sorting quality summaries already used in practice.

\subsection{Spatial Template-Footprint Features}

When a neuron spikes, an extracellular probe records that activity on multiple channels, which makes the overlap of waveforms a practical problem (see Figure \ref{fig:probe-waveform}). Information about this spatial footprint, such as the number of active channels, centre of mass, and depth on the probe, allows the model to understand where the spike is positioned relative to the probe and how concentrated or diffuse its spatial footprint is.

On the probe displaying ground-truth unit 7, the template pattern is clear and the peak amplitude decreases as the signal leaves the peak channel. This may reflect spike overlap between nearby neurons or a more difficult spatial footprint for the sorter to recover reliably. Looking at a neuron's activity across channels helps capture the full spectrum of its behaviour and its confusability.

The information that spatial-footprint features bring to the model is that units impacting multiple channels with overlapping spatial footprints are often harder to sort than others.

\subsection{Isolation, Confusability, and Recording Context}

Another important type of information is how similar each unit is to its neighbouring units. Among the features used to describe this, we used cosine-similarity features on waveforms and autocorrelograms together with other numerical variables. This helps build a feature family counting potentially confusable neighbours. It tells the model whether a unit is clearly distinct or resembles multiple units, and to what extent.

In the modelling stage, we add context features to certain models to determine whether recording information helps the model adjust to differences between recordings and between paired families. These features include within-recording means, standard deviations, medians, interquartile ranges, deviations from the recording median, and percentile-rank versions of selected unit features. The benefit of these features is that they give the model a local baseline. The model is not judging a unit only on its absolute value, but also on whether it is abnormally large, noisy, stable, contaminated, or confusable relative to the other units in the recording.

\section{Matching Units with Ground Truth}

In order to verify whether the spike-sorting algorithm correctly detected the ground-truth unit, we measure a unit-accuracy score against a defined threshold:

\begin{equation}
\text{gt\_accuracy}(u) = 1 - \fpos(u) - \fmiss(u)
\end{equation}

where, for each ground-truth unit $u$,

\begin{itemize}
    \item $\fpos(u)$ is the false-positive rate, namely extra spikes wrongly assigned to the unit.
    \item $\fmiss(u)$ is the false-negative rate, namely true spikes that were missed.
\end{itemize}

We then compare this accuracy against a chosen threshold that often ranges from 0.5 to 0.8. In our experiments, we set the threshold at 0.5 to categorise a well-identified unit while still retaining the best matched paired units used in the packaged target benchmark.

\section{Model Families}

\subsection{Stacking}

Stacking is an ensemble-learning method introduced by \textcite{WOLPERT1992241}, where one or multiple first-stage models are used to build additional inputs for the second-stage learner. It is implemented by augmenting the dataset seen by the second-stage learner with predictions made by previous specialised models. These added features are often referred to as meta-features. Stacking works for both regression and classification tasks; it has been applied to regression by \textcite{Breiman1996-xk} and to classification by \textcite{Leblanc01121996}.

As this problem relies on multiple sources of information (recordings), which differ both in nature and reliability, stacking makes it possible to add information from different sources for the final model to learn to use. Signals derived from hybrid simulation data, recording-level context, pseudo-labels from unlabeled paired data, and waveform-based representations each provide useful but insufficient evidence about unit quality. After the meta-features are added to the dataset, the second-stage learner, in our case trained on labelled paired ground-truth data, learns how much to trust each of the meta-features (predictions of the first-stage models) for a given unit. Treating intermediate predictions as fallible meta-features is especially relevant during important domain shift, because predictions derived from hybrid simulation data cannot be assumed to transfer uniformly to paired ground-truth data.

\subsection{Retained First-Stage Signals}
\label{sec:first-stage-signals}

The core stacked benchmark configurations differ by the first-stage configuration they expose to the second-stage learner, relative to the baseline references in \cref{tab:baseline-models}.

\begin{itemize}
    \item \textbf{\texttt{source\_pred}} is a scalar regression prediction produced by a LightGBM \parencite{Ke2017} teacher trained on labelled paired ground-truth rows, using full context alongside a raw importance-weighted hybrid prediction. Out-of-fold and held-out predictions are propagated forward as a transferred first guess of the target metric. It provides the second stage with an initial estimate of the outcome, so the final model can start from an informed prediction instead of having to infer everything from scratch.
    \item \textbf{\texttt{anchor\_fp\_score}} is a scalar probability in $[0,1]$ from a gradient-boosted classifier trained to distinguish labeled matched rows from unlabeled paired-pool rows, using masked context and unit features. It acts as a global unlabeled-pool-likeness score. It provides information about whether the unit looks like the broader population the model may encounter at deployment, which is useful because a unit can be realistic and important even if it is not well represented in the labeled set.
    \item \textbf{\texttt{matched\_support\_conf}} is a scalar confidence in $[0,1]$ derived from a PCA-based neighbourhood support model that converts distance to labeled neighbours into an exponentially decaying confidence. It provides a measure of how much nearby labeled evidence exists for the unit, meaning whether the model is predicting in a familiar region with close known examples or in a more isolated region where transfer is less certain.
    \item \textbf{\texttt{anchor\_support\_margin}} is the difference between the two previous signals. This signed scalar captures disagreement between global and local structure. It provides a simple summary of tension between looking like real unlabeled data and being well supported by labelled examples.
    \item \textbf{\texttt{wf\_embed\_\*}} is a low-dimensional vector learned by a convolutional autoencoder trained on waveform bins from hybrid and non-test paired data. It provides shape-based information about the waveform itself, which is useful when biologically meaningful differences between units are visible in morphology but are not fully captured by standard summary features.
\end{itemize}

\subsection{Retained Model Configurations}

We developed different model configurations by combining selected first-stage models with a second-stage predictor, as shown in \cref{tab:first-stage-configs}. The second-stage model is a gradient-boosted tree model \parencite{Friedman2001GBM}, as these models are known to perform well on tabular data with limited sample sizes. The choice between LightGBM \parencite{Ke2017} and XGBoost \parencite{ChenGuestrin2016} for the second-stage model was made empirically, selecting the one that delivered the best results.

\paragraph{Predicting both \fpos{} and \fmiss{}.}
\begin{itemize}
    \item \textbf{Paired-only context.} Paired-only context added recording-context features, but no additional first-stage outputs. It helps evaluate how much value recording context provides to the model on its own. This model is used for predicting both \fpos{} and \fmiss{} using LightGBM \parencite{Ke2017}.
\end{itemize}

\paragraph{Predicting \fpos{}.}
\begin{itemize}
    \item \textbf{Context-first source stack.} Context-first source stack is a stack configuration used to predict \fpos{}. It leverages the meta-features given by \texttt{source\_pred}, \texttt{anchor\_fp\_score}, \texttt{matched\_support\_conf}, and \texttt{anchor\_support\_margin} in its final prediction. Additionally, the dataset used by the second-stage model includes the same recording-context features used by the paired-only context model. Additionally, the second-stage learner used is LightGBM \parencite{Ke2017}.
    \item \textbf{Trust-filtered unlabeled stack.} Trust-filtered unlabeled stack predicts the \fpos{} target using the same four meta-features as the Context-first source stack. However, the second-stage model, which uses XGBoost \parencite{ChenGuestrin2016}, is also trained on selected pseudo-labelled rows that pass a trust filter. This trust filter selects unlabelled units whose predicted labels are consistent across the teacher model, are similar to nearby labelled examples, and are kept and reused for training in the second stage.
    \item \textbf{Waveform-augmented stack.} The Waveform-augmented stack predicts the \fpos{} target. Its configuration builds on the Context-first source stack by adding learned latent waveform features, using \texttt{wf\_embed\_\*}, to the second-stage model, which is XGBoost \parencite{ChenGuestrin2016}. It therefore combines transferred tabular signals with an explicit representation of waveform shape. This model combines context features, transferred tabular signals, and a latent representation of each unit's waveform shape.
\end{itemize}

\paragraph{Predicting \fmiss{}.}
\begin{itemize}
    \item \textbf{Reduced-latent context.} Reduced-latent context was retained for predicting the \fmiss{} target. It leverages the meta-features \texttt{source\_pred} and \texttt{anchor\_fp\_score}, and its second-stage model is LightGBM \parencite{Ke2017}. Its goal is to evaluate whether the transfer signal could remain stable under the \fmiss{} target.
\end{itemize}

Every model was evaluated for both targets, but only the ones performing better and providing relevant information were kept in our analysis.

The models are evaluated across 20 seeds, allowing us to assess their performance on different recording-disjoint splits. Additionally, evaluating across multiple seeds also affects model stochasticity and pseudo-label selection, thereby affecting both disjoint and leave-one-family-out splits. Leave-one-family-out splits hold out one entire family of the training set in order to evaluate the model generalisation capabilities to new data.

\subsection{Metrics}

We optimised our models around two metrics. The first metric is \rsq{}, in order to quantify the explanatory power of each of our models, by comparing the models output to the ground truth values of \fpos{} and \fmiss{}. A model with a higher \rsq{} captures a greater proportion of the variance in the target variable. The second metric is \mae{}, which helps us quantify how far our predictions of \fmiss{} and \fpos{} are from the ground truth. We prefer \mae{} over mean squared error because it is easier to interpret on our shared 0 to 1 target scale and is less sensitive to outliers.

As mentioned previously, we run each model across 20 different seeds. This allows us to average \rsq{} and \mae{} across all 20 seeds, accounting for both model stochasticity and differences in dataset splits.

\subsection{Train-test split}

For recording-disjoint evaluation, we ensure that 100 of the 207 labelled paired ground-truth units are reserved for testing to provide a sufficiently large and stable held-out set for robust model comparison. 

For the leave-one-family-out protocol, the test set consists of the family being evaluated labelled data, while the train-test set is composed of the four other paired family labelled units.

\subsection{Evaluating Feature Importance}

To evaluate feature importance, we use SHAP values \parencite{lundberg2017unifiedapproachinterpretingmodel} to understand which feature a specific model relies on most to make its prediction. To simulate a realistic scenario, we evaluate the model's performance on the LOFO protocol. We compute the mean absolute SHAP value for each feature. We then aggregate the absolute SHAP values of each feature across the 5 held-out model families for each of the 20 seeds. This provides an average feature importance along with its standard deviation across the 100 different models (5 models per seed, one per paired data family). This allows us to identify which features and feature families contribute most on average, but also how stable that contribution was across all the different seeds and held-out families.

\subsection{Leakage Prevention}

To prevent potential data leakage, we create a recording key from the recording family and recording name. This recording key ensures that no overlap exists between held-out recordings in the test set and the training sets, as well as the unlabeled pool. 

\subsection{Data Reproducibility Measures}

In order to ensure full reproducibility of the research, multiple measures were put in place:

\begin{itemize}
    \item The data used in this thesis are frozen and saved, so all figures and tables can be reproduced rather than relying on temporary notebook outputs.
    \item The repository contains a \texttt{reproducibility} folder, which includes the conda environment and environment snapshot that record the Python version and environment metadata used to run the code.
    \item The use of seed 42 was consistent throughout the entire code, including within external libraries, except for training and evaluation, which were run from seed 42 to 61.
    \item The \texttt{reproducibility} folder contains a README document giving the command sequence to reproduce the results, notebooks, figures, and environment snapshot.
    \item The SpikeForest data extraction was performed on Google Colab using the standard CPU and extended RAM settings, while all other runs were performed on the 14-core Apple silicon M3 Max CPU.
\end{itemize}
